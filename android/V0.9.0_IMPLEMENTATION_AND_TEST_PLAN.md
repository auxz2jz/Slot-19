## Changes
1. **Normal phone rotations preserve work:** MainActivity AndroidManifest adds `configChanges=orientation|screenSize|smallestScreenSize|keyboardHidden`; `onConfigurationChanged` no longer destroys/recreates coordinator and its thread pool. Persistent diagnostic state transition names active phase. CameraX PreviewView remains the same view and resizes. This is a bounded lifecycle fix for normal rotation, not a guarantee against forced Android process death, app background termination or all resource/configuration changes; device tests still required.
2. **Calibration before any video is supported:** `calibrateCheckerboard` unbinds idle CameraX camera preview while CPU/native OpenCV processes a 9×6 checkerboard, Compose restarts CameraX binding after completion. The photo working limit is 1200px max axis (instead of 1800) to bound peak memory. Staged `calibration_in_progress.json` marker helps identify abrupt process death, and last attempt/events remain. Calibration-only ZIP permitted via Export ALL Runs + Calibration Diagnostics when no capture runs exist. This directly addresses unnecessary camera resources and lack of diagnostic export. **There was no first-run crash stack trace:** we cannot claim the root crash is certainly fixed; user must retest before-video calibration.
3. **Object marked BEFORE object-specific ORB / sparse reconstruction:** After saved video frames, tap **Select Object BEFORE Sparse 3D**. The same v0.8.1 two-step large-photo selector presents saved frames index 0 and 6 (or last if <7), stores two normalized rectangles in `early_object_focus_selection.json`; does not depend on or modify any existing PLY. After tapping **Analyze Sparse 3D — Two Views**, the existing full-scene algorithm runs unchanged, preserving original PLY + source projection map. If the full scene yields `SPARSE_CANDIDATE`, a separate independent ORB pass at increased feature budget 2400 detects keypoints ONLY within the selected rectangles, matches features, runs a second independent two-view essential-matrix pose/triangulation and writes `sparse_object_focus.ply` if quality gates pass; saves method, feature counts, parallax/reprojection, failure/inconclusive status to `object_focus_report.json`. If object candidate fails, original scene PLY persists. As an opt-in additional option, existing **Select Object in Two Photos** AFTER 3D continues its original subtractive filter.
4. No automatic checkerboard intrinsics application; user calibration source geometry previously incompatible with video aspect/lens/crop, so scale UNKNOWN. New object-priority PLY is in its **own separate arbitrary coordinate system**, not registered to full scene or global multi-view SfM. More keypoints are possible, not guaranteed: low texture, motion blur and geometrically degenerate ROI can be inconclusive. Box may include background; do not claim semantic segmentation.
5. Both diagnostic ZIPs include early ROI coordinates, final focus reports, calibration-specific attempt/events/interrupted marker but NEVER raw source photos or original camera recording. Export file naming remains from BuildConfig installed version.
