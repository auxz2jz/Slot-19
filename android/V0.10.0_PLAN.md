## Initial multi-view reconstruction — bounded, honest experiment
After importing video, select object in both real source photos BEFORE 3D, then Analyze Sparse 3D for full scene plus independent ROI first-pair model. New explicit button **Build Multi-View Object Cloud — Experimental** runs a NEW 2400-feature ROI-first source-pair matching step and checks up to 8 later saved frames (7,9,13,... when available). For each additional frame:
1. Match descriptor tracks between original anchor image and extra frame; estimate its 3D-to-2D camera pose with robust PnP RANSAC using existing ROI source XYZ anchor tracks. Reject insufficient tracks/inliers or >3px median reprojection.
2. For previously UNRECONSTRUCTED anchor-image feature tracks with reliable matches in the extra frame, triangulate using original first-camera projection and that PnP-registered third-camera projection, in the original ROI-local 3D coordinate frame.
3. Enforce positive depth for BOTH cameras, bounded distance, ≤2.5px stereo reprojection, 0.8–30° triangulation angle, finite XYZ, one point per anchor feature, max 5000 total vertices. Record per-frame matches, PnP inliers, error and actual new accepted XYZ count.
4. A multi-view cloud is only marked candidate when at least TWO additional registered frames actually contribute >=4 NEW triangulated points total. Otherwise INCONCLUSIVE, with no fake PLY and an honest report. Baseline unchanged. This is true incremental multi-view **point accumulation** but NOT dense MVS, bundle adjustment, a globally optimized SfM pipeline, semantic foreground masking, calibrated scale or a mesh.
5. Different photographed backgrounds may still appear inside user-selected rectangles; more points alone DOES NOT prove the object is recognizable or accurate.
